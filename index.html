Manual y Guía de Agent Skills

Una referencia completa, interactiva y estructurada para entender, crear y mantener Agent Skills (archivos SKILL.md) con tecnologías web nativas.

🎯 Objetivo de este Manual

Una Agent Skill es un paquete de instrucciones y recursos que un agente de IA puede cargar bajo demanda para realizar una tarea específica. Este manual explica su anatomía, el frontmatter, el modelo de trigger y el ciclo de auditoría de wording — todo en una SPA 100% vanilla.

Capítulo 01

Conceptos Clave

Skill, SKILL.md, progressive disclosure, trigger model, aislamiento.

1. ¿Qué es una Skill?

Una skill es un módulo autocontenido que enseña a un agente cómo hacer algo. Se compone de un SKILL.md (instrucciones + metadata) y recursos opcionales (scripts ejecutables, assets de referencia). El agente la carga solo cuando la necesita, lo que evita saturar el contexto con instrucciones que no se van a usar.

📝
SKILL.md
Frontmatter + instrucciones Markdown.
├─
⚙️
scripts/
Scripts ejecutables referenciados en el cuerpo.
└─
📦
assets/
Plantillas, esquemas, ejemplos pesados.

2. Principios fundamentales

  • Aislamiento: cada skill vive en su propia carpeta y se describe por sí misma.
  • Progressive disclosure: el SKILL.md cabe entero en el contexto; los assets grandes se cargan bajo demanda.
  • Trigger declarativo: la description del frontmatter dice al agente cuándo usar la skill.
  • Precedencia: si dos skills compiten, la de mayor precedencia (definida por el host) sombrea a la otra.

Capítulo 02

Estructura de una Skill

SKILL.md + scripts/ + assets/; frontmatter YAML; convenciones.

1. Layout de directorios

Estructura de archivos 
mi-skill/
├── SKILL.md          # obligatorio: frontmatter + instrucciones
├── scripts/
│   └── run.sh        # opcional: scripts referenciados
└── assets/
    └── template.json # opcional: recursos pesados bajo demanda

2. Ejemplo mínimo de SKILL.md

Markdown + YAML frontmatter 
---
name: pdf-to-markdown
description: Converts a PDF to clean Markdown. Use when the user asks to extract
  text or restructure content from a PDF file.
license: MIT
---

# PDF to Markdown

## Steps
1. Read the PDF with the `pdf-extract` script.
2. Normalize headings, lists and tables.
3. Return the result as Markdown.

## Reference
See `assets/format-rules.md` for edge cases.

Capítulo 03

Frontmatter y Metadata

name, description, license, allowed-tools; validación y precedencia.

1. Campos del frontmatter

Campo Requerido Propósito
name Sí Identificador de la skill (kebab-case).
description Sí Dice al agente cuándo usarla. Es el contrato de trigger.
license No Licencia SPDX (MIT, Apache-2.0...).
allowed-tools No Restringe las tools disponibles mientras la skill está activa.
⚠️

Regla de la description

Describe el qué y el cuándo, no el cómo (eso va en el cuerpo). Una mala descripción = trigger errático. Itera el wording con pruebas reales.

Capítulo 04

Discovery y Trigger

Descripción declarativa, invocación /name, sombreado por precedencia.

1. Modelo de trigger

El agente descubre las skills disponibles y decide cuál cargar en runtime. Dos caminos:

  • Declarativo: el razonamiento del agente compara el mensaje del usuario contra las description de todas las skills y elige la pertinente.
  • Explícito: el usuario invoca /nombre-de-la-skill, que fuerza la carga sin ambiguity.

2. Sombreado por precedencia

Si dos skills pueden matchear el mismo mensaje, el host resuelve por precedencia: la skill de mayor nivel (p. ej. workspace > usuario > plugin) sombrea a la de menor nivel. Esto permite sobrescribir skills empaquetadas sin editar el paquete original.

Capítulo 05

Progressive Disclosure

Cargar pasos/assets solo cuando se necesitan; no inflar el contexto inicial.

1. La regla del contexto mínimo

El SKILL.md debe caber entero en el contexto del agente. Los assets pesados (plantillas largas, catálogos, esquemas JSON grandes) no se embeben en el cuerpo: se referencian y se cargan solo si la conversación los necesita.

2. Patrón de referencia bajo demanda

SKILL.md (fragmento) 
## Pasos
1. Detecta el formato de entrada.
2. Si hay tablas complejas, lee `assets/table-rules.md`
   para aplicar las reglas de merge de celdas.
3. Devuelve el Markdown resultante.

Aquí assets/table-rules.md solo se carga si aparecen tablas complejas — el contexto inicial permanece ligero.

Capítulo 06

Crear → Testear → Mantener

Flujo de autoría, validación de frontmatter, iteración de wording.

1. Flujo de autoría

  • Crear: escribe SKILL.md con frontmatter y cuerpo minimalista.
  • Validar: comprueba que name y description existen y son precisos.
  • Testear: lanza escenarios reales y observa si el agente la trigerea correctamente.
  • Iterar: ajusta el wording de description hasta que el trigger sea estable.
✅

Señal de que la skill está lista

Se trigerea de forma fiable en ≥ 90% de los escenarios previstos y no se trigerea en escenarios ajenos.
